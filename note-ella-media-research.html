From a link to an answer, safely

Four request types kept apart, URL rules that assume hostile input, and research whose citations can be checked.

On this page

  2. Fetching media from a link
  3. URL rules that assume hostile input
  4. Search that does not pretend
  5. Relevance without overclaiming
  6. Research that can be checked

01Four paths, kept separate

A request that involves the web can be web research, a search for an existing public-domain or licensed asset, a fetch of one explicit public link, or generation. Intent precedence keeps them apart. A bare link on a recognized platform is a fetch request. An ordinary article link stays web research. Searching for an existing asset stays asset search, and generation stays generation.

02Fetching media from a link

One fetch pipeline handles direct public HTTPS files and public links on an exact allowlist of platforms. It has distinct modes for downloading, extracting audio, transcribing and analyzing, runs a pinned version of the extractor, and has focused tests for intent collisions and retries.

03URL rules that assume hostile input

Opening a URL blocks embedded credentials, unusual ports, local, private and reserved addresses, unsupported schemes and unsafe redirects. Page content is untrusted and cannot override instructions or permissions.

Two honest caveats are written into the project. Network egress restrictions are still recommended on top of application checks, and DNS rebinding between validation and connection is a residual risk that application code alone cannot remove.

04Search that does not pretend

Search results must come from live provider output, because a model's answer is not proof of a search. Every source-specific claim needs a direct URL. Publication date is not retrieval time, and a missing date stays missing. A failed search must not trigger a roundup made up from memory. A claim of a screenshot requires a real image, and song lookups return legal listening links and short previews, not downloads.

05Relevance without overclaiming

Image and video search gathers candidates across providers, removes duplicates by source page and ranks them on titles, tags, descriptions and the original request. Poor metadata matches are rejected, and when nothing fits the answer is a not-found result, not a random picture. The check is metadata-based, not pixel-level, and the docs say so. Captions say a result was retrieved, never generated.

06Research that can be checked

The web workspace adds a scraper with bounded extraction, sitemap discovery, focused crawling and quote-verified field extraction, and a research mode that plans, searches, reads, takes quote-backed notes, checks for gaps, writes a cited report and checks citations sentence by sentence. Citation checking is not a truth guarantee, and the system says so.

Autonomous agent tasks run under step, page, model and time budgets and can pause, resume, cancel and ask for approval. Crawls over 15 pages need approval, and in assisted mode every sandbox run does too. Fetched pages are treated as untrusted data, and the note-taking steps that read them have no tools. Robots rules are honoured.

These routes are off unless explicitly switched on, and the docs say not to enable them on a public host until network egress blocks private and metadata address ranges.
